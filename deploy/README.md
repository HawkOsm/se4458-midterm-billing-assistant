# Deployment (AWS, eu-north-1)

The files in this folder are what was sent to AWS. They are concrete: account 860897619048,
image tag `b233fe8` (the git commit), and the real endpoints, so they show exactly what runs.
Like the instructor's `apiNode` (`ecs-express-service.json`), each service is one ECS Express
Mode file.

| File | What it is |
| --- | --- |
| `express-api.json` | billing REST API (`node dist/index.js`) |
| `express-mcp.json` | MCP server (`node dist/mcp/http.js`) |
| `express-agent.json` | AI agent and chat page (`node dist/agent/server.js`) |
| `migrate-task.json` | one-off ECS task: migrations + demo data (`tools` image) |
| `iam/*.json` | trust policies of the two roles, and the execution role's secrets policy |

## What exists

| Resource | Name / ID | Notes |
| --- | --- | --- |
| ECR repository | `billing-assistant` | tags `b233fe8` (services; `706006d` and `75e6a33` were earlier deployments) and `tools-706006d` (job); immutable tags, scan on push, keeps the last 10 |
| IAM role | `ecsTaskExecutionRole` | pulls the image, writes logs, reads only `billing/*` secrets; trusted only for this account |
| IAM role | `ecsInfrastructureRoleForExpressServices` | lets Express Mode create the load balancer, security groups, certificates |
| Secrets Manager | `billing/db-password`, `billing/jwt-secret`, `billing/gateway-secret`, `billing/provider-api-key`, `billing/anthropic-api-key` | the first four generated by AWS, never printed |
| RDS | `billing-db`, PostgreSQL 17.11, db.t4g.micro, 20 GB gp3 | encrypted, not public, TLS required (verified with `certs/`) |
| Security group | `billing-db` (`sg-04025df5f3d5169fa`) | port 5432 only from the API's and MCP's security groups, and the VPC default group (migrate job) |
| ECS cluster | `default` | Fargate |
| ECS Express services | `billing-api`, `billing-mcp`, `billing-agent` | 0.25 vCPU, 0.5 GB, exactly 1 task each; one shared HTTPS load balancer |
| API Gateway (HTTP API) | `billing-gateway` (`e57dg4znaj`) | `ANY /{proxy+}` to the billing API, adds `X-Gateway-Secret`, throttled to 10 req/s (burst 20) |

Express Mode's defaults are 1 vCPU, 2 GB and up to 20 tasks, so the files set `cpu`, `memory`
and `scalingTarget` explicitly.

**Cost** (AWS price list, eu-north-1): about $2.7 a day while it runs, mostly Fargate
(3 × $0.0136/h), the load balancer ($0.024/h), RDS ($0.016/h + storage) and public IPv4
addresses ($0.005/h each).

## Order of the steps

The order matters: each step needs something from the one before.

1. Build and push the images (`docker build .`, `docker build --target tools .`).
2. ECR repository, IAM roles, secrets.
3. RDS and its security group; wait until it is available.
4. Run `migrate-task.json` once (tables + demo data). It must finish before the API and MCP
   start: they check the database at startup.
5. `express-mcp.json` and `express-api.json`; their URLs come back from the create call.
6. The HTTP API: integration to the API's URL with
   `overwrite:header.x-gateway-secret` set to the secret, route `ANY /{proxy+}`, stage
   `$default` with throttling.
7. `express-agent.json`, with the gateway URL and the MCP URL filled in.
8. Replace the database's temporary VPC-wide rule with the services' own security groups
   (Express Mode creates them in step 5, so they can't be known earlier).

## Updating the code

Build and push a new tag, then update each service's image (for example with
`aws ecs update-express-gateway-service`). Express Mode rolls out the new task and keeps the old
one until the new one is healthy.

## Teardown

Delete in reverse order: the three Express services (this also removes their load balancer,
target groups and security groups), the HTTP API, the RDS instance (skip the final snapshot for
a demo), the `billing-db` security group and DB subnet group, the secrets, the task definition,
the log groups, the IAM roles and the ECR repository.
